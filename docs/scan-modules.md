# План модулей Scans

Scans организован в Recon и Vulnerability Analysis. Круглый переключатель карточки выбирает технику. Можно выбрать одну или несколько. Start scanning ставит выбранные реализованные задачи в очередь текущего проекта. Значок информации открывает описание, значок настройки — выбор приложений и параметры. История, отмена задач и артефакты доступны ниже.

Включаются задачи из серверного каталога. Отсутствующие бинарники отображаются с причиной недоступности. Выбор техники не меняет утверждённую область сканирования. Наблюдения и сетевые обращения используют действующие ограничения scope.

Цели в интерфейсе Scans берутся автоматически из утверждённого Scope текущего проекта. Повторно вводить Domains, Targets, IP addresses или начальные URL в настройках модулей не нужно. Для DNS- и web-задач используются разрешённые DNS Name, для IP-задач — записи IP address; сети не разворачиваются в полный список адресов. Исключения и серверная проверка scope продолжают действовать. Если подходящих записей нет, интерфейс предлагает добавить их в Scope до запуска. DNS wordlist создаёт отдельную задачу для каждого разрешённого домена.

## Subdomain Enumeration

Назначение — поиск поддоменов и определение IP-адресов найденных имён.

- **subfinder** — быстрый пассивный сбор поддоменов из публичных источников и API. Реализован адаптер subdomains.subfinder. Домены берутся из Scope, используется стандартный набор источников subfinder. При включённом Resolve IP addresses найденные поддомены проходят проверку A/AAAA. В Assets публикуются только имена с адресами и найденные IP. DNS-проверка разрешена для поддоменов утверждённого исходного имени, включая exact_domain, с учётом исключений исходного и текущего Scope. Это разрешение относится к DNS-проверке при обнаружении. Для подключений продолжают действовать точные правила host/IP. Имена без адресов, ошибки DNS и исключённые имена сохраняются в rejected артефакта задания. При выключенной опции сохраняются пассивные имена без DNS-проверки. Assets содержит накопленную историю, прежние записи автоматически не удаляются. API/CLI сохраняет возможность явно задавать домены и источники.
- **ffuf** — запланирован режим поиска поддоменов. Возможность использования готового Go-бинарника рассматривается отдельно от языка основного Rust-приложения.
- **dnsmap** — задача `dns.wordlist`: выбор списка `default` (полный встроенный словарь dnsmap 0.36, 989 слов) и 4/8/16 параллельных исполнителей, по умолчанию 8. Список делится между процессами dnsmap, каждое слово проверяется одним исполнителем. Wildcard определяется LasTest по случайным разрешённым именам; найденные имена повторно проверяются по A/AAAA. Исключения исходного и текущего Scope применяются до запуска; изменение Scope останавливает процессы. Для DNS-обнаружения разрешены дочерние имена утверждённого DNS Name, включая exact_domain; разрешения на подключения не расширяются. Лимита 5000 слов нет. Загрузка пользовательских списков через Settings запланирована; API-параметр `words` сохраняется для совместимости.
- **Certificate Transparency** (`subdomains.discover`) использует Cert Spotter. Поле Providers выбирает источник данных; поскольку сейчас поддержан один источник, интерфейс показывает его название вместо свободного ввода. Лимит 50 доменов снят для CT и Subfinder.
- **DNS records** (`dns.records`) запрашивает записи имён из Scope, а не перебирает поддомены. `record_types` ограничивает типы запросов: A — IPv4, AAAA — IPv6, CNAME — псевдоним, MX — почтовый сервер, NS — сервер имён, TXT — текстовые данные. Пустой список означает эти шесть типов. PTR доступен для явных IP-целей через API/CLI.
- Доступны задачи subdomains.discover (Certificate Transparency), dns.records и dns.wordlist (dnsmap с проверкой результатов в Rust). Это самостоятельные задачи. При выборе нескольких задачи ставятся в очередь отдельно, без автоматической передачи результатов между ними. Существующий API цепочек сохраняется.

## Asset Discovery

Назначение — выявление цифровых активов компании, IP-адресов, сетевых диапазонов/ASN и облачных хранилищ.

- **hakrevdns** — массовые обратные DNS-запросы.
- **theHarvester** — пассивный OSINT-сбор о домене и компании.
- **WhatWeb** — определение CMS, веб-серверов, фреймворков и библиотек.
- Сейчас подключена reverse.ip — PTR и пассивные reverse-IP провайдеры. ASN, облачные хранилища и перечисленные внешние инструменты остаются в плане. HTTP technology hints доступны в HTTP Probing.

## Web Crawling

Назначение — сбор URL, параметров запросов, скрытых страниц и файлов.

- **gau** — известные URL из Wayback Machine, Common Crawl и AlienVault.
- **waybackurls** — исторические URL из Wayback Machine.
- **Katana** — обход ссылок, форм и endpoints, в перспективе с рендерингом JavaScript.
- Сейчас доступны urls.passive (Wayback/CDX и Common Crawl), http.crawl (ограниченный HTML-обход) и paths.discover (словарь путей). Внешние gau/waybackurls/Katana и JS-рендеринг запланированы.

## HTTP Probing

Назначение — проверка доступности URL, статуса ответа и заголовков.

- **httpx** — планируемый инструмент для массовой проверки доменов и URL.
- Сейчас подключена Rust-задача http.probe с режимами root/url, статусом, заголовками и technology hints.

## Port Scanning

Назначение — поиск открытых портов на доменах и поддоменах с учётом разрешённых IP.

Для Nmap запланированы три режима.

1. Веб-порты.
2. 1 000 популярных портов.
3. Определение ОС и дополнительной информации после обнаружения открытых портов.

Сейчас доступны tcp.connect и отдельно установленный nmap.profile с фиксированным unprivileged service-профилем. IP берутся из записей IP address в Scope, порты выбираются в настройках. OS detection и NSE запланированы.

## Network Vulnerability

Назначение — поиск известных сетевых уязвимостей.

- **sqlmap** — автоматизация проверки SQL-инъекций. Положение в этой группе сохранено из продуктового плана, при этом его целями являются веб-приложения.
- **Nmap** — скрипты проверки уязвимостей.
- **Nuclei** — шаблоны известных проблем и CVE.
- Реализованных задач этой группы пока нет, карточка недоступна для запуска.

## WEB Vulnerability

Назначение — поиск известных уязвимостей веб-приложений.

- **Nmap** — web-скрипты проверки уязвимостей.
- **Nikto** — проверки веб-серверов, опасных файлов, устаревшего ПО и конфигурации.
- **Nuclei** — шаблоны известных проблем и CVE.
- Сейчас подключена web.checks — версионированные Rust-проверки HTTP/TLS, HSTS, срока сертификата и Secure cookie. Полный каталог Nuclei, Nikto и NSE остаются в плане.

## Subfinder и установка

Docker-образ содержит официальный готовый subfinder 2.17.0 для amd64/arm64 с проверкой фиксированной SHA-256 суммы. Go toolchain для запуска не требуется. Лицензия поставляется в /usr/share/licenses/subfinder/LICENSE.md.

Для запуска без Docker задайте LASTEST_SUBFINDER_PATH с путём к установленному бинарнику. При отсутствии бинарника модуль остаётся в каталоге с available: false.

Настройки TOML subfinder_timeout_seconds (по умолчанию 150), http_timeout_seconds, max_artifact_bytes и max_queue_targets ограничивают процесс и результат. Параметры команд формируются адаптером. Отмена и изменение scope останавливают процесс, вывод ограничен, DNS-разрешение выполняется существующим Rust DNS-клиентом.

Каждый старт создаёт задачи с идемпотентными ключами. Если часть задач отправилась, повторная попытка в текущей странице использует те же ключи для уже отправленных задач. После полного успешного старта следующий старт создаёт новый запуск.

Документация subfinder — https://github.com/projectdiscovery/subfinder/tree/v2.17.0.
