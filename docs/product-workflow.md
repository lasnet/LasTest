# Модель работы LasTest

Текущая продуктовая договорённость от 22 ноября 2026 года. При изменении поведения модулей обновлять этот документ вместе с реализацией. Исходный проект в AGENT-ARCHITECTURE.md описывает историю архитектуры; актуальный пользовательский процесс описан здесь.

## Project → Scope → Assets → модули

Project — главная сущность. Scope проекта содержит DNS name, IP address и Network, включая исключения. Scope задаёт разрешения, Assets — инвентарь и единственный источник выбора целей последующих модулей. Результаты остаются внутри проекта. Поля ручного ввода доменов, IP и URL в настройках модулей не нужны.

Subdomain Enumeration берёт DNS name из Scope, ищет/проверяет имена и публикует имена с подтверждёнными A/AAAA в Assets. Не требуется запускать его в проекте только с IP/Network.

Перед любым другим модулем, если Assets пусты:

- Scope пуст: предложить сначала заполнить Scope.
- Есть разрешённые DNS name: предложить сначала запустить Subdomain Enumeration.
- DNS name нет, есть IP/Network: показать подтверждение импорта IP из Scope в Assets. Network раскрывается сервером в отдельные IP с ограничением размера; превышение лимита не допускает частичный импорт. Импорт не сканирует сеть, не меняет Scope и не обходит исключения/политику сети.

Если Assets уже есть, повторный запуск Subdomain Enumeration не обязателен. Смешанный проект использует существующие Assets; добавление новых правил в Scope само по себе не добавляет цели в очередной запуск.

## Модули

- Asset Discovery обрабатывает имеющиеся Assets (DNS и связанные IP либо отдельные IP), объединяет пассивные данные, DNS, обогащение и классификацию. Confidence и interest независимы. Повторные запуски обновляют одну запись хоста/адреса, а не создают строки для каждого источника. Найденные внешние имена остаются кандидатами до разрешённой проверки. Информация открывается справа в выдвижной панели поверх текущего экрана. Настройки источников и опционального HTTP находятся в настройках модуля; запуск общий для выбранных модулей.
- Web Crawling требует сохранённого выбора хостов из Assets в настройках. Выбор: DNS name / IP, Confidence / interest, поиск, выбрать все подходящие, снять выбор, сохранить, отменить. Пустой выбор при запуске открывает настройки. Обход ограничен выбранными хостами.
- HTTP Probing использует аналогичный выбор доменов/хостов, у которых в Assets есть URL после сбора/обхода. Проверяет сохранённые URL выбранных хостов, без подстановки произвольных корней или истории другого хоста. Если URL нет, предложить Web Crawling.
- Port Scanning использует аналогичный выбор Assets, проверяет их IP. Настройки содержат наборы портов и ручной ввод портов через запятую. Нет отдельного поля ввода целей.
- Network Vulnerability и WEB Vulnerability впоследствии также используют Assets; детальный процесс новых интеграций пока не определён. Существующие web.checks сохраняются.

При включённом Active HTTP enrichment worker дополняет встроенные признаки результатами WhatWeb для Jenkins и jQuery. WhatWeb анализирует локальный снимок ответа. LasTest отвечает за HTTP-запрос и проверку Scope на редиректах. Стандартный Docker-образ задаёт путь к WhatWeb автоматически. Для worker вне Docker путь задаётся через `whatweb_path`.

Выбор относится к проекту и модулю, сохраняется только кнопкой Save; Cancel не меняет выбор. При смене проекта окна закрываются и выбор очищается. Недоступные интеграции остаются недоступными.

## Просмотр Assets

Вверху Assets находятся три отдельные вкладки: **Hosts and IP addresses**, **Discovery candidates** и **URLs**. Одновременно показан только выбранный раздел; по умолчанию открываются хосты и IP. Поиск, фильтры и страницы таблиц сохраняются при переключении вкладок. Details открывает существующую боковую панель выбранного хоста или кандидата. Ссылки `#assets`, `#assets/candidates` и `#assets/urls` позволяют открыть нужный раздел напрямую; вкладки поддерживают клавиатурную навигацию стрелками, Home и End.

## Settings

Раздел Administration → Settings доступен администратору без выбора проекта. General меняет тему в текущем браузере.

- В **API** у каждого провайдера одна строка с приложениями и действием для добавления или замены ключа. Для сохранённого ключа видны последние четыре символа. Worker использует его при старте задачи, без отдельной настройки ключа в Scans. Cert Spotter работает в Subfinder и Certificate Transparency, Censys PAT — в Subfinder и Asset Discovery (Reverse IP), SecurityTrails, Shodan и VirusTotal — в Subfinder.
- В **WordList** администратор загружает именованный TXT в UTF-8 с одной DNS-меткой или префиксом на строку. В **Scans → Subdomain Enumeration → Settings → dnsx** выбираются список (`default` или сохранённый ID), параллельность 4/8/16 (default 8), частота DNS-запросов (default 50/с) и resolver Dedicated/System. Dedicated использует `LASTEST_DNS_WORDLIST_RESOLVER` (default `1.1.1.1:53`); внутренние имена требуют соответствующего DNS. Общий таймаут всей задачи — `LASTEST_DNS_WORDLIST_TIMEOUT_SECONDS` (default 7200 секунд).
- CT, Subfinder, DNS records и другие готовые задания имеют приоритет перед словарём. Словарь ждёт завершения уже выполняющихся заданий. На установку работает один перебор, включая несколько worker: захват атомарный в SQLite, процесс дополнительно держит файловую блокировку. Позже поступившие обычные задания могут выполняться при активном переборе; частота словаря ограничена и при System DNS. Этапы цепочек сохраняют зависимости и не блокируются своими будущими этапами.
- A/AAAA, повторы, wildcard и TCP fallback перебора используют один ограничитель реальных исходящих DNS-запросов. Scope проверяется до отправки и публикации; нет fallback с отдельного DNS на системный. В Assets публикуются только проверенные адреса. При NXDOMAIN/NODATA ошибки не добавляются; неотвеченные имена остаются в `unprocessed`.
- Прогресс и проверенные Assets сохраняются в SQLite примерно раз в секунду и перед финализацией. Отмена/таймаут сохраняют частичный JSON с `checked`, `unprocessed`, `stop_reason`, адресами и признаком полноты. В Job history видны оставшиеся имена и **Download saved result**; сохранённый результат доступен даже после аварии worker. Неполное завершение показывается как **Incomplete**, отмена — **Cancelled** с сохранёнными данными.

## Разрешения и совместимость

Сервер разрешает ID целей только из текущего проекта. При постановке задачи фиксируется снимок выбранных Assets. Перед выполнением проверяются их наличие, текущий Scope и политика сети. DNS-имя, найденное под разрешённым DNS name, допускается к последующим проверкам только как выбранный Asset; исключения имеют приоритет. Для проверки связанных IP повторно проверяются A/AAAA: допускается только пересечение адресов снимка Assets и свежего DNS. Это разрешение относится только к задаче и не добавляет IP или домены в Scope. Сужение Scope и отмена применяются к следующим запросам. Метаданные выбора создаёт сервер, клиент не может прислать готовое разрешение.

Низкоуровневые API/CLI с явными параметрами и прежняя цепочка All in one сохраняются для совместимости. Новый интерфейс отправляет ID Assets; ручные старые API по-прежнему требуют обычного явного разрешения Scope. Assets не отменяют сетевую политику и не разрешают произвольные адреса.

## Завершение и ошибки отдельных проверок

В интерфейсе `succeeded` и `partial` отображаются как Completed: выполнение задачи завершено, результаты сохранены. Ошибки источников или отдельных целей отражаются ненулевым красным счётчиком Errors. Текст ошибок по умолчанию скрыт в Error details; раскрытие сохраняется при обновлении истории. Failed означает сбой задачи, Interrupted и Cancelled остаются отдельными состояниями. Технические статусы API/очереди и правила продолжения цепочек сохраняются; `partial` не переименовывается в базе.

Отсутствие PTR (NXDOMAIN/NODATA) и пустой ответ пассивного источника — обычный пустой результат. `not_permitted` — пропуск кандидата за пределами Scope. Они не увеличивают Errors. SERVFAIL/REFUSED, таймауты, сетевые ошибки и активное HTTP-обогащение без единого полученного ответа сохраняются как ошибки проверок. Подробности неудачного HTTP (URL и причина) доступны в данных обогащения и summary-артефакте; одного сообщения `HTTP enrichment failed` недостаточно для вывода о причине.
